Equity Briefing — 产品说明书

版本：1.0（V1 已交付上传 Agent + Deck）
状态：V1 可用
定位：买方分析师助理 · 证据型财报简报 Agent
范围：研究工具，不构成投资建议

1. 一句话定义

Equity Briefing 是一个面向专业投资者视角的 财报分析 Agent：用户上传财报文件（或输入股票代码），系统实时抽取实质信息，用表格、图表与可审计结论，输出一份 类似分析报告 PPT 的可视化简报。

2. 要解决的问题

现状痛点 产品如何解决
财报又长又密，人工划重点慢 Agent 自动抽取关键科目、KPI、风险句，并标页码证据
聊天式 AI 输出难演示、难分享 固定结构的 deck 简报（一页一主题），可翻页、可导出
模型容易编造数字 数字只来自解析与校验层；叙事层禁止发明新数字
“目标价很确定”不可信 估值（若开启）只给保守区间 + 假设 + 失效条件，不作点预测神谕
结论无法追溯 每条 claim 绑定原文摘录 / 行情来源链接

3. 目标用户

  • 个人投资者 / 买方研究员：快速吃透一份 10-K、年报、业绩材料
  • 投研助理 / 实习生：生成可二次编辑的研究底稿
  • 非财务背景决策者：用可视化简报理解“公司这一期到底怎样”

非目标用户：需要下单执行、量化回测交易、或合规投顾牌照服务的场景（本产品明确不做）。

4. 产品原则

  1. 证据优先：没有来源的数字不出示；没有证据的结论不升级为“确定”。
  2. 实质信息优先：少形容词，多科目、同比、现金流、风险原文。
  3. 可视化优先：表 > 图 > 短结论；长段落降级为附录。
  4. 一页一主题：像分析 PPT，不像信息仪表盘。
  5. 保守表达：涉及估值时，展示保守锚定与假设，不承诺“未来最可能股价”。
  6. 人机分工：工具负责解析与计算；模型负责提炼与叙事，且受 schema 约束。

5. 使用模式

5.1 上传财报模式（主路径 · v1 核心）

用户上传财报文件 → Agent 解析 → 流式生成 PPT 式简报。

支持输入（分阶段）：

阶段 格式 说明
v1 PDF（可选文本层） 10-K / 10-Q / 年报 / 业绩演示 PDF
v1.1 PDF + Excel/CSV 用户自备三表或管理层 KPI 表
v2 扫描件图片 OCR 后进入同一流水线

用户操作流：

  1. 进入「上传财报」
  2. 拖入文件（可附可选：公司名 / ticker / 报告期提示）
  3. 查看解析进度（页数、表格识别、科目抽取）
  4. 简报按页流式出现（先封面与快照，再图表，再风险）
  5. 点击任意结论 → 打开证据抽屉（原文摘录 + 页码）
  6. （可选）导出 PDF / 分享链接

5.2 Ticker 模式（辅路径 · 现有能力演进）

输入美股代码或公司名 → 拉取公开行情与财务 → 生成同一套 deck 结构的简报。
可与上传模式组合：上传定“质”，行情定“价”（可选页）。

6. 简报结构（PPT 式 Deck）

默认 8–12 页。每页包含：标题、一句结论、一个主视觉（表或图）、底部证据条。

页序 页名 主视觉 内容要点
01 封面 品牌 + 标的信息 公司、报告类型、期间、分析时间、数据来源
02 执行摘要 要点列表 亮点 1–3、风险 1–3；各带页码引用
03 财务快照 多期对比表 收入、毛利、营业利润、净利、FCF、现金、债务
04 趋势 折线 / 柱状图 收入与利润趋势；利润率结构
05 盈利质量 对照表 + 红旗 经营现金流 vs 净利、应计、一次性、稀释/回购
06 分部与 KPI 表格 分部收入/利润；管理层强调 KPI 是否可验证
07 风险重点 编号卡片 从 Risk Factors / MD&A 抽出可执行的 5 条
08 叙事 vs 数字 双栏对照 管理层说法 ↔ 报表是否支持
09 （可选）估值 区间图 + 假设表 保守合理价值区间、现价位置、失效条件
10 附录证据 摘录列表 原文片段、页码、访问渠道

文案规范：

  • 结论句使用条件性措辞（“在…假设下”“披露显示…”）
  • 禁止无条件“强烈买入 / 目标价必达”
  • 中英双语可切换（与现有产品一致）

7. Agent 能力说明

7.1 流水线

上传/拉取 → 解析分块 → 结构化抽取 → 数字校验 → 可视化装配 → 叙事生成 → Deck 输出
模块 职责 实现约束
Parser 提取文本、表格、页码；扫描件走 OCR 确定性工具优先
Extractor 按 schema 输出科目、期间、KPI、风险句 JSON Schema 约束；缺字段显式标 missing
Validator 勾稽检查、单位统一、同比重算 校验失败则降级展示并提示
Visualizer 生成表/图所需结构化数据 前端渲染；禁止模型直接画“假图数据”
Narrator 生成标题、要点、失效条件 不得引入未在 Extract 中出现的数字
Editor 证据绑定、拒收无 evidenceIds 的 claim 与现有 Editor 纪律一致

7.2 “划重点”如何定义

不是高亮全文，而是产出：

  • 可点击的 Claim（立场：支持 / 谨慎 / 中性 / 条件性低估·合理·高估）
  • 绑定 Evidence（文件页码、摘录、或 Yahoo/EDGAR 链接）
  • 假设清单（若涉及预测或估值）

7.3 估值页（可选 · 保守原则）

当且仅当识别到可靠 ticker 且财务数据充分时展示：

  • 保守合理价值区间（多模型偏低分位 + 安全边际）
  • 现价相对区间位置 → 条件性低估 / 大致合理 / 条件性高估
  • 失效条件（如 FCF 连续为负、杠杆超阈值、关键假设被证伪）
  • 明确标注：保守锚定 ≠ 未来最可能成交价

不做：用 LLM 直接报目标价；用单一分析师目标价冒充内在价值。

8. 界面与交互

8.1 信息架构

  • 首页：双入口 —「上传财报」/「输入代码」
  • 生成中：进度条 + 已完成页缩略
  • 简报台：横向/纵向翻页（PPT 感）；侧栏页目录
  • 证据抽屉：统一打开原文/链接
  • 设置：语言（中/EN）、是否启用估值页、缓存刷新

8.2 可视化组件清单

  • 多期财务对比表
  • 收入 / 盈利 / FCF 趋势图
  • 利润率对比柱图
  • 52 周价格位置（Ticker 模式）
  • 情景或保守价值区间带状图（估值页）
  • 风险等级条（L1–L5）
  • Peer P/E 对照（有同行数据时）

8.3 实时体验

  • 流式 NDJSON / SSE：按页推送
  • 单页失败不阻断整份简报（该页显示“数据不足”）
  • 缓存：同一文件指纹 / 同一 ticker 24h 可复用（可强制刷新）

9. 数据与合规

9.1 数据来源

来源 用途
用户上传文件 主分析对象
Yahoo Finance 实时行情、公开财务报表（Ticker 模式）
SEC EDGAR CIK、披露链接、（后续）XBRL/摘录
FMP / Finnhub 等（可选 Key） 更稳的历史财务、同行

9.2 隐私与安全

  • 上传文件仅用于生成当次/缓存期内的研究简报
  • 不将用户文件用于模型训练宣传口径（产品承诺需在部署时落实）
  • 密钥仅存服务端环境变量
  • 对外分享链接默认脱敏或需显式授权

9.3 免责声明（产品内固定展示）

本产品为研究原型工具，输出不构成投资建议，亦不构成买卖要约。请对照原始披露与自建模型核对所有数字后再做决策。

10. 成功标准（验收）

体验

  • 一份标准文本层 PDF（≤50 页）在可接受时间内出齐核心页（封面→风险）
  • 用户无需读完整份 PDF，即可从 deck 理解本期实质变化
  • 任意关键数字可点开追溯到摘录或外部来源

质量

  • 校验层能拦下明显加减/单位错误
  • Narrator 不出现 Extract 中不存在的金额
  • 数据不足时拒答点位，而非编造估值

形态

  • 简报可按页浏览，观感接近分析报告 PPT
  • 支持中/EN
  • 研究免责声明始终可见

11. 版本路线图

版本 主题 交付

12. 明确不做（Non-goals）

  • 自动下单 / 模拟盘交易
  • 保证收益或“必涨”点位
  • 无证据的荐股话术
  • 用单一聊天窗口替代结构化简报作为唯一交付物
  • 对所有行业强行输出同一套 DCF 点预测

13. 与现有技术资产的关系

当前仓库已具备：Next.js App Router、流式报告 API、证据/Claim 模型、图表与双语 UI、Yahoo + EDGAR 采集、确定性分析管道。

产品演进策略：保留证据纪律与分析模块，新增「上传解析」与「Deck 呈现层」，将现有长页报告重构为可翻页简报，而不是推倒重来。
